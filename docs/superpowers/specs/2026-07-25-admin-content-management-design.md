# 后台内容管理入口设计

## 目标

为 STAFF 和 ADMIN 提供明确可发现的“内容管理”页面，使其能够查看并删除已经发布的帖子，同时查看和恢复仍在 14 天保留期内的帖子。作者仍在“我的”页面管理自己的帖子。

## 界面与导航

- 后台侧边导航新增“内容管理”，路径为 `/admin/content`。
- 页面分为两个不嵌套的内容区域：“已发布”和“待清理”。
- 已发布列表展示标题、作者、发布时间和删除按钮。
- 待清理列表展示标题、删除者、保留截止时间和恢复按钮。
- 删除操作需要确认；删除或恢复成功后立即从当前区域移除，并刷新另一对应区域。
- 操作期间按钮禁用，失败时显示简体中文错误提示。

## API 与权限

- 新增 STAFF 可访问的 `GET /api/admin/published`，复用仓储的公开帖子列表并返回管理所需的完整修订数据。
- 删除和恢复继续复用现有 `DELETE /api/stories/:storyId` 与 `POST /api/stories/:storyId/restore`。
- 后端既有权限规则不变：STAFF/ADMIN 可删除任意帖子；恢复仍遵循删除记录与保留期规则；手动 GC 仍仅 ADMIN 可用。

## 测试与验收

- 路由测试覆盖普通用户不可访问、STAFF 可读取已发布列表。
- 前端测试覆盖导航入口、已发布帖子删除、待清理帖子恢复及操作失败提示。
- 全量测试、生产构建和 Wrangler dry-run 必须通过。
