# 帖子延迟删除、恢复与 R2 GC 设计

## 目标

为帖子增加作者与管理员删除能力，同时保留 14 天恢复窗口。删除期间帖子立即从公开内容中隐藏；作者可恢复未修改的帖子，管理员可恢复管理员删除的帖子。保留期结束后彻底删除 KV 数据、索引和不再被引用的 R2 对象。R2 删除失败进入 GC 队列，由每日 Cron 和管理员手动操作重试。

## 权限

- 帖子作者（`ownerGithubId` 对应当前用户）可以删除和恢复自己的帖子。
- `STAFF` 与 `ADMIN` 可以删除任意帖子；为与需求一致，二者都可以恢复管理员删除的帖子。
- 删除和恢复均要求登录；匿名用户没有相关权限。
- 已删除帖子不出现在公开列表、公开详情、热门排行或点赞接口中。
- 作者可以在 14 天保留期内编辑自己删除的帖子；编辑不会让帖子重新公开，也不会自动取消删除。

## 数据模型

在 Story KV 元数据旁新增删除记录：

```ts
interface StoryDeletion {
  storyId: string;
  deletedAt: string;
  purgeAt: string;
  deletedByGithubId: string;
  deletedByRole: "USER" | "STAFF" | "ADMIN";
  previousStatus: StoryStatus;
  revisionId: string;
  contentHash: string;
}
```

`contentHash` 使用 SHA-256，输入为当前修订中稳定的业务内容：标题、正文、匿名标志、图片的 `assetId`、顺序和说明。输入不包含状态、时间戳或审核元数据，避免单纯状态变化被误判为内容修改。

删除时保留现有故事记录与修订，写入删除记录并移除/标记公开索引；`purgeAt` 为 `deletedAt + 14 天`。删除记录和待 GC 项使用可列举的 KV 前缀，支持 Cron 分页处理。

## 删除流程

1. 读取故事元数据和当前修订。
2. 校验调用者是作者，或角色为 `STAFF`/`ADMIN`。
3. 若已删除，返回冲突错误，不重复覆盖原删除记录。
4. 计算当前修订 `contentHash`，记录删除者、删除前状态和修订 ID。
5. 将故事标记为删除，并移除公开索引；保留 KV 修订、作者索引和图片元数据。
6. 删除公开帖子对应的点赞入口或使其对已删除故事返回 404；点赞数据可在过期清理阶段删除。

删除操作应具备幂等保护，避免重复请求延长 14 天保留期。

## 恢复流程

### 作者恢复

作者只能恢复自己删除的帖子。删除期间允许作者保存新的当前修订，但不允许在恢复前直接提交审核。读取删除记录后重新计算当前修订哈希：

- 哈希与删除记录一致：恢复 `previousStatus`，重新建立相应公开/审核索引；
- 哈希不一致：恢复为 `draft`，不直接公开，作者必须重新提交审核。

### 管理员恢复

`STAFF`/`ADMIN` 可恢复管理员删除的帖子，恢复到删除前 `previousStatus`。若删除者是普通作者，管理员恢复仍依据作者删除规则：内容未改则恢复原状态，内容已改则恢复草稿，避免绕过重新审核。

恢复成功后删除删除记录，停止该帖子的过期清理计时。恢复为草稿或待审核时重新建立作者/待审核索引；恢复为公开时重新建立公开索引。

## 14 天彻底删除

Cron 或手动 GC 找到 `purgeAt <= now` 的删除记录后：

1. 再次读取故事和删除记录，确认仍处于删除状态，避免误删已恢复帖子。
2. 删除该故事的所有修订、元数据、作者索引、删除记录和关联索引。
3. 收集所有修订中的 R2 `assetId/objectKey`，逐项检查是否仍被其他未删除故事引用。
4. 未被引用的对象调用 `MEDIA.delete`；成功后删除资源元数据。
5. R2 删除失败不阻塞 KV 清理，将对象键写入 GC 队列并记录重试时间。

彻底删除后，公开详情、作者列表、审核列表和恢复接口均返回 404。

## GC 触发与队列

- 在 `wrangler.jsonc` 增加通用 `triggers.crons`，每日运行一次，不包含账号专属配置。
- Worker 导出 `scheduled` handler，调用统一 `runGarbageCollection(env)`。
- 管理后台增加 `ADMIN` 专用 `POST /api/admin/gc`，立即运行同一 GC 服务并返回处理统计；`STAFF` 不能执行全局物理清理。
- GC 队列使用 KV 前缀保存对象键、失败次数和下次重试时间；每次运行限制批量大小，避免超时。
- R2 删除操作应可重复；对象已不存在视为成功。

## API 与前端

新增认证 API：

- `DELETE /api/stories/:storyId`：作者或 STAFF/ADMIN 删除；
- `POST /api/stories/:storyId/restore`：按上述作者/管理员规则恢复；
- `POST /api/admin/gc`：仅 ADMIN 手动运行 GC。

账号页为作者帖子提供删除/恢复操作；管理员审核或故事管理视图提供删除、恢复和运行 GC 操作。删除按钮需要确认，处理中禁用，成功后刷新列表，失败显示错误。公开画廊不显示已删除帖子。

## 错误处理

- 无权限返回 403；不存在或已彻底删除返回 404；重复删除/恢复返回 409。
- R2 删除失败记录日志和 GC 队列，不向用户暴露存储内部错误。
- GC 单个对象失败不影响同批次其他对象处理。
- 计算哈希和 KV 更新失败时不写入部分删除记录，接口返回 500 并保留原帖子可见性。

## 测试与验证

覆盖以下单元和集成行为：

- 作者和 STAFF/ADMIN 权限；普通用户不能删除他人帖子；
- 删除后公开查询隐藏、作者查询可见删除状态；
- 作者未修改恢复原状态，修改后恢复草稿；
- 管理员恢复管理员删除帖子；
- 14 天前不彻底删除，过期后清理 KV；
- R2 未引用对象删除，删除失败进入 GC 队列并可重试；
- Cron 与手动 GC 使用同一服务；
- API 和前端按钮成功、失败、重复请求状态。

完成后执行：

```bash
npm test
npm run build
npx wrangler deploy --dry-run
```

## 非目标

- 不引入 D1 或新的持久化数据库；
- 不改变现有审核角色名称；
- 不立即物理删除用户帖子或图片；
- 不提供超出 14 天的普通用户恢复能力；
- 不让 GC 删除仍被其他故事引用的 R2 对象。
